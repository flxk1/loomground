# v0.8 punch-list

Items carried out of the v0.7 cycle. Sources: the clean-room implementation
built from the spec text alone (three runs, 44/44), the adversarial consistency
review of the principal-chain change, and the deployment due diligence that
opened the cycle. Nothing here blocks v0.7; each item is either a cheap pin, a
testability gap, a profile, or a companion document. Grouped by kind, cheapest
first.

## A. Spec-text pins — one sentence and/or one vector each

1. **Rack-expansion failure stage.** SYNTAX §7 says a failed expansion
   (unknown rack, arity mismatch, undefined `$name`, missing `end`) is
   ill-formed, but no text or vector pins *parse* vs *apply*. The natural
   reading: parse (the pre-pass precedes the grammar). Pin it; add
   `reject-rack-*` negative vectors.
2. **`obligation … on <undeclared gate>` stage.** Unpinned; the clean-room
   implementation guessed apply (consistent with every other undeclared-node
   case). One sentence in SYNTAX, one negative vector.
3. **Provenance non-mutation.** The spec never says whether evaluation appends
   traversed nodes/parties to the token's `provenance`. Both implementations
   do not mutate it, and quorum distinctness reads it as *presented*. State
   that evaluation reads and never writes `provenance` (the transport supplies
   it), or specify the append rule; either way, pin with a vector.
4. **Quorum canonical spacing.** §9 says "insignificant whitespace removed",
   but the canonical form is actually *normalised* — exactly one space after
   `of` and after each comma, none inside braces (`2 of {legal, finance}`) —
   derivable today only from `reserve-quorum/expected.json`. One sentence.
5. **The ungated step-(4) default.** §7.1 leaves the `auto`/`human` disposition
   at a gate with no required grade to policy (§10), yet every transport vector
   pins `auto` there — conformance de facto fixes the policy default. Resolve
   the tension: either make `auto` the normative default absent a declaration,
   or give the surface a policy-default declaration and re-derive the vectors.

## B. Testability gaps

6. **The obligation-withhold branch is untestable from the surface.** §7.3
   releases only if "every egress obligation is attached", but a declared
   obligation is always attached — nothing can be un-attached, so the withhold
   branch of the master rule has no vector and never fires. Either give the
   transport a way to present a non-attached obligation, or state explicitly
   that attachment failure is a host-side condition outside conformance.
7. **Two-implementation criterion as CI.** Reproduction by RVND and
   loomground-ref is currently attested in prose (conformance README, Status).
   Consider a machine-checkable attestation: each implementation publishes a
   signed result manifest (vector name → pass, standard commit), and the
   standard's CI fetches and checks both before a release tag.

## C. Profile track — additive conformance profiles, core stays frozen

8. **Rooted-chain profile (P5 of the principal chain).** Every actor's
   principal chain terminates at a `human` or a party-bearing actor — the
   "no unaccountable agent" property. Deliberately kept out of v0.7 core;
   define it as a named profile with its own vectors.
9. **Run-scope profile.** A declared scope over consecutive activations by the
   same actor: sticky verdicts (a `prohibited` kind stays prohibited for the
   run — the join extended across activations, restrictive direction only) and
   approval carry-over (`reserve <kind> by <role> covers <duration|count>`).
   The temporal condition is the template: declared threshold + declared
   resolution, measurement host-side.
10. **Budget profile.** `budget <kind> <n> per run: halt` — cumulative-effect
    governance (spend caps, call counts, blast radius). Same declare/measure
    split as temporal; the missing piece for agent-gateway deployments.
11. **Escalation declaration.** `escalate <kind> after <n> refused to <role>`
    — repeated `refused`/`reserved` in a run refers to a human instead of
    allowing indefinite retry. Host counts; language declares.

## D. Companion documents — not spec changes

12. **Security considerations.** The spec grounds in RFC-culture sources but
    has no security-considerations section. Minimum contents: a published
    patch enumerates its prohibitions and reserved kinds (a map for an
    adversary choosing `kind` labels); verdicts key on self-declared `kind`
    and `tags` (the robots.txt user-agent problem) — name attested-assignment
    as a deployment requirement and point to a future attested-kind profile.
13. **Discovery convention.** Where does an agent, gateway, or auditor find
    the patch governing an endpoint or tool? A `/.well-known/loomground.lg`
    convention and/or a field in MCP tool metadata. Out of scope for the spec
    (transport), decisive for adoption; robots.txt won on a known location.
14. **External-witness profile for the log.** §7.4's tamper-evident log is
    produced by the party that enforces. A profile naming an external witness
    (CT-style) is what makes the accountability story credible to a regulator.
15. **Spec-governance process.** CONTRIBUTING, a change process for the
    standard itself, a versioning/deprecation policy beyond the `.loom`
    precedent, and who decides what lands in a release.

## Landed in v0.7 (for the record)

The principal chain P1–P4 (`proposals/principal-chain.md`), the empty-set
corner of no-amplification, the effective-verdict log wording (§7.4),
at-most-one delegator, nearest-wins party inheritance, the `.loom` alias
closure, single Apache-2.0 licensing, and the §9 two-implementation criterion
met by RVND and loomground-ref at tag v0.7.0.
